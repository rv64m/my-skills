# 论文精读

产出一份**三个月后重看仍然有用**的中文笔记。读完笔记的人应该能回答：

- 论文解决什么问题，为什么值得解决；
- 方法具体如何工作；
- 可以用来做什么，适用边界是什么；
- 证据是否足以支撑作者主张；
- 要复现还缺什么。

## 三个常见失败

1. **复述摘要不等于读过。** 笔记的价值在于机制为什么 work、证据链哪里断了、复现要踩什么坑。
2. **区分作者主张、实验证据与读者推断。** 三者混在一起，笔记无法用于后续决策。
3. **保留不确定性。** 没看懂的公式、对不上的数字和含糊设置写进「存疑」，不要猜测补全。

## 流程

### Phase 0 — 侦查

先盘点 PDF：

```bash
pdfinfo paper.pdf
pdffonts paper.pdf
pdftotext -layout paper.pdf paper.txt
```

通读 title、abstract、intro 末尾贡献列表、conclusion 与各级标题，建立结构地图，并判定论文类型：

| 类型 | 核心要看 |
|---|---|
| 新方法 (method) | 机制、消融、基线公平性 |
| 实证研究 (empirical) | 识别策略、数据、稳健性 |
| 理论 (theory) | 假设强度、结论边界、假设是否可检验 |
| 基准/数据集 (benchmark) | 构造过程、污染、是否可被刷 |
| 综述 (survey) | 取材范围、分类法是否有解释力 |

AI/ML/CS 论文读 **references/ml-cs-lens.md**；金融/经济论文读 **references/econ-fin-lens.md**。交叉领域两份都读。

### Phase 1 — 先提问，再精读

基于 abstract + intro 写下 5–8 个可证伪、可回答的问题，并先在对话里亮出来。至少覆盖：

- **问题**：现有方法具体卡在哪里？这个诊断成立吗？
- **机制**：核心改动是什么，为什么会起作用？
- **证据**：什么结果会推翻主张？作者做了吗？
- **复现**：最可能缺哪块信息？
- **代价**：收益换来了多少算力、数据、调参或泛化损失？
- **用途**：如果方法有效，谁能在什么场景使用？论文是否真的验证了该用途？

用户若说明要复现、写综述或做评审，据此调整问题权重。

### Phase 2 — 逐节精读

按 method → experiments → intro/related work → appendix 的顺序读。appendix 常藏有实验细节与负面结果。

**数字必须回表核对。** 记录数值对应的数据集、模型、指标、切分与比较对象；不要直接复述“显著优于”“提升 40%”。

**公式必须还原成直觉。** 对每个核心公式说明每一项控制什么、去掉会怎样、边界情况下退化成什么。无法解释的内容放进「存疑」。

### Phase 3 — 提取图表

架构图、主结果表和关键消融必须进入笔记本体：

```bash
python scripts/extract_figures.py paper.pdf -o <notes_dir>/figures --dpi 150
```

脚本按 caption 裁剪图、表和算法框，也能处理矢量图。提取后逐张目视检查，只保留架构图、主结果、关键消融和有解释力的曲线。若 caption 定位失败，使用 `pdftoppm` 渲染对应页面并裁剪。

每张图配**自己的解读**：它想证明什么、实际证明到什么、是否缺方差/关键基线、坐标轴是否误导。不要只翻译 caption。

### Phase 4 — 重建方法

不用作者的叙述顺序，重新建立：

- **符号表**：统一记号、形状和取值域；
- **自绘数据流图**：用 Mermaid 从输入画到输出或损失；
- **关键公式直觉**：解释控制项与边界行为；
- **伪代码**：写到可实现粒度，包括张量形状、循环边界、梯度处理与损失组合。

画不出来或写不到实现粒度的地方，进入「存疑」。

### Phase 5 — 审问

逐条核销 Phase 1 问题：已答 / 部分 / 未答。建立「主张 → 证据 → 强度」台账：

- 证据直接支持主张，还是只支持更弱版本？
- 基线是否同预算、同数据、同调参投入？
- 消融能否把功劳归因到声称的机制？
- 作者承认了什么局限？还有什么未承认的局限？
- “可以用来做什么”是论文实证验证的用途，还是基于机制的合理推断？

用途部分必须标清证据边界。不要把潜在应用写成已经证明可用；对不适用的场景也要明确说明。

### Phase 6 — 成稿

用户指定输出目录时遵从用户目录；否则写入 `/mnt/user-data/outputs/<论文短名>-notes.md`。图片放同目录 `figures/` 并使用相对路径。

语言为中文，专业术语保留英文原词。成稿必须满足：

- 开头使用 **「总结」**，不再使用「一句话」；总结用一小段概括问题、方法、关键证据和结论边界，不强制压成一句；
- 元信息表中的 **「论文」只放论文主页链接**，不写本地文件路径、下载路径或“本次阅读源”；
- 在元信息表后单列 **「解决什么问题」** 和 **「可以用来做什么」**；
- 「解决什么问题」同时写清现实/研究痛点与旧方法为何不足；
- 「可以用来做什么」给出具体用户、场景和动作，并区分已验证用途、合理推断与不适用边界；
- §1、§4、§6、§8 不能省，分别承担快速回顾、证据审计、复现和诚实标注。

## 笔记模板

```markdown
# <论文标题>

> **总结**：<解决什么问题；核心方法；最关键定量证据；证据支持到哪里、边界在哪里。可用 2–4 句。>

| | |
|---|---|
| 作者 / 机构 | |
| 发表 | <venue, year> |
| 类型 | <新方法 / 实证 / 理论 / benchmark / 综述> |
| 论文 | [论文主页](<URL>) |
| 代码 / 数据 | <链接，或「未公开」> |
| 一句话定位 | <它在这条研究线上处于什么位置> |

## 解决什么问题
写清现实或研究痛点、受影响对象，以及现有方法具体不足。不要只改写 abstract。

## 可以用来做什么
- <已被论文实验直接验证的用途：谁，在什么场景，执行什么动作>
- <基于方法机制的合理扩展；明确写“可能”或“可探索”>
- **适用边界**：<哪些场景不能直接用，或需要与什么方法结合>

## 0. 读前问题与核销

## 3. 图表精选

数据、划分、基线、评价指标、算力。

| | | 强 / 中 / 弱 / 未支撑 | |

同等预算？最强基线还是方便基线？

- **作者未承认但存在的问题**：
- **我不同意的地方**：
- **什么结果会推翻它**：

- **可复现度**：高 / 中 / 低 —— 理由
- **齐备**：
- **缺失**：<超参、数据预处理、随机种子、算力>
- **成本估计**：<数据 / GPU 时 / 工程量>
- **最小可行复现路径**：

## 7. 对我有用的
- 可直接拿走的想法 / 技巧：
- 值得追的引文：

没读懂的、对不上的、需要外部确认的。保留这一节，不要为了完整而猜测。
